# Building from source

To get the app without setting anything up, [build it on GitHub](github-build.md).
This page is for building GLUE 5 on your own computer, and for working on
it.

## Quick start

```sh
git clone https://github.com/mempage4k/glue5
cd glue5
ln -s /path/to/your/game game   # b/<build>/game.wasm, b/<build>/shaders, data
mise run play                   # the first build compiles ~1 GB of generated C
```

`game.wasm` is translated to C with [wasm2c] at build time, compiled with
the platform's C compiler and linked into a Rust host that provides the
engine's imports, threads, files, input, audio and GPU. The build checks
`game.wasm` against the supported build; `GLUE5_GAME_DIR` can point at the
game folder instead of the `game` link.

## Version identity

The semantic version stays in the workspace `Cargo.toml` at `0.1.0` until
the user asks to change it. `VERSION_CODENAME` adds one neutral, lowercase
word to identify a distinct build, independently of the semantic version;
`0.1.0 willow` identifies the
current build. Keep the word for retries or rebuilds of the same source, and
choose a new word when a meaningful code change makes a new build to
identify—even when the SemVer stays `0.1.0`. The word is not a prerelease
label and says nothing about stability or release state. Avoid terms that
imply status or have a special build meaning, such as `alpha`, `beta`,
`release`, `draft`, `main` or `function`.

Android's `VERSION_CODE` is a separate, positive, monotonically increasing
integer used only for APK update ordering; increment it for every APK intended
to update an existing installation. It is not derived from Cargo SemVer or
`VERSION_CODENAME`. The Android `versionName` combines the Cargo version and
codename, while `targetSdk` is independently set in
`platform/android/gradle.properties` (`36` at present).

## Requirements

[mise] and a C/C++ compiler. mise installs Rust, CMake and [xcodegen] on
first use (`.mise/config.toml`), and for Android the JDK, Gradle, the SDK's
command-line tools and cargo-ndk; the Android tasks install the SDK
packages they need with sdkmanager (versions in
`platform/android/gradle.properties`).

Every task first runs `mise run setup`, which prepares wgpu, wgpu-core,
wgpu-hal and wasm2c with [our patches](../patches/README.md) (only when
they change), and fetches the other sources the build takes at pinned
versions (Luau, libadrenotools for Android, ...). Run cargo by hand through mise too: in a shell with
`mise activate`, or `mise exec -- cargo ...`.

Compiled C objects are cached in `target/glue5-tools/objcache`, shared by
debug and release builds: later builds only recompile what changed.

## Platforms

### iPhone and iPad

Xcode is required. `mise run ios [device]` builds, signs, installs and
launches the app with its console. Signing uses the team in `GLUE5_TEAM`:
put it in `.mise/config.local.toml` (ignored by git) under `[env]`.
`mise run ios:ipa` makes an unsigned IPA for a sideloading tool to sign;
`mise run ios:game [device]` copies the game into the app's
`Documents/game`.

An Xcode project generated by xcodegen from `platform/ios/project.yml`
links the crate as a static library.

### Apple TV

The same as iOS (`mise run tvos [device]`), with Xcode's tvOS platform
(Xcode › Settings › Components) and an Apple TV paired with Xcode (on the
TV: Settings › Remotes and Devices › Remote App and Devices).
`mise run tvos:sim` runs it in the simulator.

### Android

`mise run android [device]` builds, installs and launches the app with its
log; `mise run android:game [device]` copies the game into the app's
`Android/data/local.glue5/files/game`. With several devices connected,
pass the serial number (`adb devices`).

As SDL's README-android describes, the Gradle project in `platform/android`
packages the crate as a shared library (`libglue5.so`, built with
cargo-ndk), SDL's own (`libSDL3.so`) and SDL's Java activity, taken from
the `sdl3-src` crate the libraries are built with.

### Mac

`mise run macos` builds `target/package/Glue 5.app` and opens it;
`mise run macos:package` also makes a DMG. They need Xcode 26 or later
for the Icon Composer icon. Builds target macOS 14 or later
(`.cargo/config.toml`). There is no Developer ID signing or notarization:
the executable keeps the linker's ad-hoc signature, and a downloaded copy
is blocked by Gatekeeper until allowed. The bundle declares the Games
category and Game Mode.

The game's files are never bundled: the app finds them next to
`Glue 5.app` or where the start page points it. `mise run play` remains
the direct cargo workflow, with the log in the terminal.

### Windows

The MSVC toolchain (`x86_64-pc-windows-msvc`), no MinGW or MSYS compiler.
Besides mise, install:

- Visual Studio Build Tools 2022 or later, with *Desktop development with
  C++* (MSVC and the Windows SDK).
- LLVM, for `clang-cl` on the `PATH` (e.g. `scoop install llvm`): the
  game's generated C is compiled with it, against MSVC's headers and
  runtime; `cl.exe` truncates the engine's longest names. `CC` overrides
  it.
- Git for Windows (the full one, not MinGit), whose bash runs the tasks.
  Set `MISE_BASH_PATH` to its `bin\bash.exe`, ahead of WSL's.
- Developer Mode (Settings › For developers), so mise can link tools.

The repository checks out with LF line endings everywhere
(`.gitattributes`). Link the game folder with a junction
(`New-Item -ItemType Junction game -Target <dir>`) or set
`GLUE5_GAME_DIR`.

### Linux

Clang compiles the game's generated C (`CC` overrides it). SDL is built
against the headers of the backends it supports: install them before the
first build (on Debian and Ubuntu, the list in `platform/linux/Dockerfile`),
or SDL leaves those out.

`mise run linux:package` builds an AppImage with cargo-packager: the
executable and the icon; glibc, Vulkan and the libraries SDL loads come
from the system, so it runs where the glibc is as new as the one it was
built with. `mise run linux:container [x86_64|aarch64]` builds it in
Ubuntu 22.04 with Docker, from any system: give Docker the memory for up
to eight C compilations of ~15 MB files at once.

## Tasks

`mise tasks` lists them all.

| What | Command |
|---|---|
| Play on this computer | `mise run play` |
| Share the game folder on the network ([streaming](streaming.md)) | `mise run serve [folder]` |
| Run without a window: scripted input, PNG shots, statistics, the benchmark | `mise run headless -- --help` |
| Tests | `mise run test`; every translated shader through naga's validator: `mise run test:shaders` |
| Record pipelines on automated runs into the app's seed | `mise run shaders:collect [levels]` |
| Merge recorded pipelines into the seed | `mise run shaders:seed <pipelines.jsonl>...` |
| A PGO profile from the benchmark | `mise run pgo` |
| A PGO profile from a phone's benchmark | `mise run pgo:android` |
| iPhone / iPad | `mise run ios`, `ios:build`, `ios:ipa`, `ios:run`, `ios:game` |
| Apple TV | `mise run tvos`, `tvos:build`, `tvos:run`, `tvos:sim` |
| Android | `mise run android`, `android:build`, `android:run`, `android:game` |
| Mac | `mise run macos`, `macos:build`, `macos:run`, `macos:package` |
| Linux | `mise run linux:package`, `linux:container [x86_64\|aarch64]` |

## Runtime options

Environment variables for the app and the headless runner.
`mise run ios`, `tvos` and `android` (and their `:run`) pass `RUST_LOG`
and `GLUE5_*` variables on to the device.

| Variable | Effect |
|---|---|
| `GLUE5_GAME_DIR` | The game folder, at build and run time. |
| `RUST_LOG` | Log filter (default `info`): renderer statistics every 10 s (frame times, CPU time per stage, memory). |
| `GLUE5_ENGINE_LOG=stdout` | The engine's log on the terminal too (it is always in `game.log` in the user folder). |
| `GLUE5_ENGINE_ARGS` | More engine switches, e.g. `-benchmark -benchmarkIterations=1`. |
| `GLUE5_DEVICE_NAME` | The name GLUE 5 Studio's pages show for this device (by default its own: the computer's or the phone's name in the system's settings; on iOS, "iPhone" or "iPad" without Apple's user-assigned-device-name entitlement). |
| `GLUE5_PLAY=1` | Start the game without the start page (`--play` on a computer). |
| `GLUE5_BENCHMARK=1` | Start the game's benchmark at once and end the app when it is over: a measurement on a phone, whose screen nobody taps (the results are in the log). |
| `GLUE5_GPU_PROFILE=1` | GPU time per render pass in the statistics. |
| `GLUE5_NO_BC=1`, `GLUE5_NO_FLOAT32_FILTER=1`, `GLUE5_NO_ETC2=1` | A phone GPU's fallbacks on a desktop GPU, for testing. |
| `GAMERESOURCEMB`, `KEEPTHREADS` | The engine's module settings, as the browser build reads them. |
| `GLUE5_ALLOW_UNKNOWN_BUILD=1` | Build against a `game.wasm` other than the supported one. |
| `GLUE5_TEAM` | The Apple development team that signs the iOS and tvOS apps. |
| `GLUE5_BUNDLE_ID` | The iOS and tvOS apps' bundle identifier (default `local.glue5`): another one when Apple says the default "is not available" to your team. |

## Optimised builds (experimental)

Off until measured on every device; Clang's own command line (not
Windows' clang-cl).

| Variable | Effect |
|---|---|
| `GLUE5_GAME_LTO=1` | ThinLTO across the game's 64 C files: inlining across them (a build of ~3 min on an M1 Pro, its link cached per target). |
| `GLUE5_GAME_PGO=<file.profdata>` | The game compiled with a profile, its functions run gathered together; `mise run pgo` makes the profile from the benchmark (`target/glue5-tools/pgo`). |
| `GLUE5_GAME_PGO=generate` | The game compiled instrumented: it writes a profile when the app ends (`mise run pgo:android` does the whole round on a phone). The profile's place is `LLVM_PROFILE_FILE`; on a phone the activity sets it (`GLUE5_PROFILE=1`). |
| `GLUE5_ANDROID_TUNE=<cpu>` | The CPU the game's C is tuned for on Android (`cortex-a78` by default, `cortex-x1`, `none` to turn it off). |

## Repository layout

| Path | What |
|---|---|
| `crates/glue5-game` | The game module: its build script checks `game.wasm`, runs wasm2c, applies the hooks and compiles the C. |
| `crates/glue5-runtime` | The engine's host: its imports, threads, files, input, audio, online and friends, the GPU command ring. |
| `crates/glue5-gpu` | The renderer: the engine's D3D11-style commands on wgpu (Metal on Apple devices, Vulkan elsewhere). |
| `crates/glue5-stream` | Streaming the game's files: `glue5-serve`, the client and its local copy, discovery on the network. |
| `crates/glue5-qos` | Thread priorities on each platform (the runtime's `qos`, the stream's threads too). |
| `crates/glue5-mods` | Mods: Luau in the game's script threads, its natives' table, and the Studio's server. |
| `crates/glue5-studio` | GLUE 5 Studio's page: Leptos (wasm) around CodeMirror. |
| `crates/glue5` | The app (SDL3), the same on every platform: window, input, audio, settings, touch controls (egui). Its `headless` example runs the game without a window. |
| `platform/` | What each platform needs around it: the iOS and tvOS project specs, the Android Gradle project, the Mac bundle's extras, the Linux container. |
| `patches/` | Our patches to wasm2c, wgpu, wgpu-core, wgpu-hal and sp-fidelity ([README](../patches/README.md)). |
| `.mise/` | The toolchain (`config.toml`) and the tasks (`tasks/`). |

`crates/glue5-game/hooks.rs` lists the game functions the host replaces,
by their wasm name; an unset hook keeps the original, and a hook can call
it through `glue5_game::orig`. Those the host only calls are listed in its
`CALLED_ONLY` too: the game's own calls then go to them directly. How the
whole thing works is in the [design notes](design.md).
